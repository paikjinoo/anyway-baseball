# Anyway Baseball ⚾

브라우저에서 즐기는 3D 야구 게임. Next.js + Three.js로 만들었고 Vercel에 배포합니다.

- **직접 하는 것**: 투구(구종 + 코스 선택), 타격(조준 + 타이밍), 도루 지시, 투수 교체, 대타·대주자·대수비
- **키우는 것**: 선수별 경험치 → 레벨 → 훈련 포인트, 골드로 티어(C/B/A/S) 강화
- **자동으로 되는 것**: 수비, 주루
- **모드**: CPU 대전 / 온라인 1:1 / **2대2 올스타전** / **2~7인 릴레이 타격 대결** / 리그
- **네트워크**: 로그인·팀·방 정보만 Firebase, 실제 경기 데이터는 **WebRTC P2P**로 직접 교환

---

## 빠른 시작

```bash
npm install
npm run dev
```

`http://localhost:3000` 접속 → **게스트로 둘러보기** → **팀 창단** → **CPU 대전**.

Firebase 설정 없이도 로컬 모드로 모든 싱글 기능(팀 편집, 훈련·성장, 리그, CPU 대전)을 쓸 수 있습니다.
한 계정에 팀은 하나입니다 — 골드와 아이템이 팀에 붙어 있어서, 팀을 여러 개 만들 수 있으면
지갑을 늘려 보상을 중복으로 모을 수 있게 됩니다.
데이터는 브라우저 `localStorage`에 저장됩니다. 온라인 대전만 Firebase가 필요합니다.

## Firebase 설정 (구글 로그인 + 온라인 대전)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다.
2. **Authentication → Sign-in method → Google**을 사용 설정합니다.
   - 승인된 도메인에 `localhost`와 배포 도메인(`your-app.vercel.app`)을 추가합니다.
3. **Firestore Database**를 만듭니다 (프로덕션 모드).
4. **프로젝트 설정 → 내 앱 → 웹 앱 추가**에서 설정값을 복사합니다.
5. 프로젝트 루트에 `.env.local`을 만들고 `.env.example`을 참고해 채웁니다.

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_FIREBASE_API_KEY=AIza...
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-app.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-app
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your-app.appspot.com
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=1234567890
NEXT_PUBLIC_FIREBASE_APP_ID=1:1234567890:web:abcdef
```

6. `firestore.rules`의 내용을 Firestore 규칙에 붙여넣고 게시합니다.

### TURN 서버 (선택)

STUN만으로 대부분 연결되지만, 대칭형 NAT 환경(일부 회사망/모바일)에서는 TURN이 필요합니다.
[Metered](https://www.metered.ca/tools/openrelay/), [Twilio](https://www.twilio.com/stun-turn) 등에서
자격 증명을 받아 `.env.local`에 넣으면 자동으로 사용합니다.

```env
NEXT_PUBLIC_TURN_URL=turn:your-turn-server:3478
NEXT_PUBLIC_TURN_USERNAME=...
NEXT_PUBLIC_TURN_CREDENTIAL=...
```

## Firestore 사용량

경기 중에는 Firestore에 **쓰기가 발생하지 않습니다.** 모든 게임 트래픽은 WebRTC
DataChannel로 흐릅니다. Firestore를 쓰는 시점은 다음뿐입니다.

| 동작 | 쓰기 |
|---|---|
| 팀 저장 / 훈련·성장 결과 저장 | 1 |
| 리그 생성 / 경기 결과 기록 | 1 |
| 방 생성 (offer 포함) | 1 |
| ICE 후보 교환 | 보통 5~15 (연결 후 삭제) |
| 방 입장 (answer) | 1 |
| **경기 1회당 (투구 300구 포함)** | **0** |

한 경기당 총 Firestore 쓰기는 약 10~20회 수준입니다.

## 조작

### 공격 (타격)
| 입력 | 동작 |
|---|---|
| 마우스 이동 / 방향키 | 배트 조준점 이동 |
| `Space` (투구 전) | 타석에 들어서기 → 상대가 투구 |
| 클릭 / `Space` | 일반타격 |
| `Shift`+클릭 / `A` | 강한타격 (판정 범위 좁고 파워 상승) |
| `S` | 번트 |
| 주자 버튼 | 도루 지시 (투구 전에만) |

### 수비 (투구)
1. 구종 선택 — 직구는 모든 투수가 보유, 변화구는 선수마다 다름
2. 존 그리드를 클릭해 목표 코스 지정 (존 바깥도 가능)
3. 퀵모션 여부 선택 (주자 있을 때) → **투구!**

제구 능력치가 낮으면 노린 곳에서 벗어납니다. 스태미나가 떨어지면 구속과 제구가 함께 나빠집니다.

## 게임 시스템

### 선수

선수는 **투수와 타자로 갈려서 생성**되며 그 구분은 바뀌지 않습니다. 플레이어가 바꿀 수 있는 건
투수의 마운드 역할(선발 4명 필수 / 중간계투 / 마무리)과 타자의 야수 포지션 9개뿐입니다.
로스터는 투수 10명(선발 4 · 중간계투 5 · 마무리 1) + 타자 13명 = 23명입니다.

**타자 (포수 포함)** — 컨택 / 파워 / 선구안 / 스피드 / 수비 / 송구
**투수** — 스태미나 + **구종별로** 구속 / 제구 / 무브먼트

선수 생성은 **총량 예산제**입니다. 능력치 합계를 좁은 정규분포에서 뽑은 뒤 포지션별
가중치로 배분하므로, 무작위이면서도 압도적으로 강하거나 쓸모없는 선수가 나오지 않습니다.

### 체형

타자는 체형을 셋 중에서 고릅니다. 능력치 수치 자체는 바뀌지 않고, 경기에 쓰이는 값에만
더해집니다 — 선수단 화면에 `파워 62 +5`처럼 함께 표시됩니다.

| 체형 | 파워 | 스피드 | 특징 |
|---|---|---|---|
| 기본 | 0 | 0 | 균형 잡힌 체형 |
| 슬림 | −5 | +5 | 가벼워 발이 빠르지만 타구가 덜 뻗는다 |
| 거구 | +5 | −5 | 타구는 멀리 가지만 발이 느려진다 |

3D 모델은 몸의 두께만 달라집니다. 키와 머리 비율은 그대로입니다 — 골격 치수는 포즈·IK와
한 세트로 튜닝돼 있어서 키를 건드리면 스트라이크존 정렬과 카메라가 함께 깨집니다.

### 티어와 레벨

모든 선수는 **C등급 1레벨**에서 시작합니다. 경기에 나가면 경험치를 받아 레벨이 오르고,
레벨이 오를 때마다 **그 선수 전용 훈련 포인트**를 받습니다. 최대 레벨에 도달하면 골드를 써서
티어를 올립니다.

| 티어 | 최대 레벨 | 능력치 상한 | 구종 슬롯 | 강화 비용 |
|---|---|---|---|---|
| C | 10 | 65 | 3 | 2,000G |
| B | 20 | 78 | 4 | 8,000G |
| A | 30 | 89 | 5 | 25,000G |
| S | 40 | 99 | 6 | — |

**티어 강화는 능력치를 전혀 건드리지 않습니다.** 레벨만 1로 돌아가고 상한이 넓어질 뿐이라,
"C 10레벨의 능력치 그대로 B 1레벨"이 됩니다. 능력치는 오직 훈련 포인트를 써야 오릅니다.

실제 상한은 **티어 상한과 선수 고유 잠재력 중 낮은 쪽**입니다. 잠재력이 70인 선수는 A등급이
돼도 70에서 막히므로, 같은 S등급 안에서도 개인차가 남습니다.

### 구종

| 구종 | 특징 | 습득 |
|---|---|---|
| 직구 | 가장 빠르고 제구가 쉽다 | 전원 기본 보유 |
| 투심 / 싱커 | 가라앉는다, 땅볼 유도 | 훈련 |
| 커터 / 슬라이더 | 옆으로 꺾인다 | 훈련 |
| 커브 / 포크볼 | 낙차가 크다 | 훈련 |
| 체인지업 | 타이밍 교란 | 훈련 |
| 너클볼 | 궤적이 무작위, 제구 매우 어려움 | 훈련 |

보유할 수 있는 구종 수는 티어가 정합니다(C 3 · B 4 · A 5 · S 6). 슬롯이 차면 티어를 올려야
하나 더 익힐 수 있습니다.

### 훈련

훈련 포인트는 **레벨업으로만** 들어옵니다. 능력치가 높을수록 1 올리는 비용이 급격히 커지고,
상한에 닿으면 티어를 강화해야 다시 자랍니다. 새 구종은 난이도에 비례한 비용으로 습득하며,
습득 직후에는 능력치가 낮게 시작합니다.

### 투수 스태미나 (경기 간 이월)

투수의 스태미나는 **경기가 끝나도 소모된 상태로 남습니다.** 등판하지 않은 경기마다 1/3씩
회복하므로, 완전히 지친 선발도 **3경기를 쉬면 가득 찹니다.** 로테이션은 경기마다 한 칸씩
돌고, 피로가 남은 채로 올라오면 그만큼 이미 지친 상태에서 시작합니다. 능력치 좋은 선발
한 명으로 모든 경기를 돌릴 수 없게 하려는 장치입니다.

투구 수가 한계를 크게 넘기면 낮은 확률로 **부상**이 생깁니다. 부상 중인 선수는 타순·로테이션에
들어갈 수 없고, 경기를 한 판 끝낼 때마다 회복이 하루씩 줄어듭니다.

### 경기 보상

경기는 **선수별 경험치와 팀 골드**를 줍니다. 아이템은 경기에서 나오지 않습니다.

- 출전한 선수만 받습니다. 타자는 안타·홈런이, 투수는 이닝과 탈삼진이 추가분의 대부분입니다.
- 난이도(이지 0.8 ~ 프로 1.6)와 승패(승 1.3 / 무 1.0 / 패 0.8)가 배수로 곱해집니다.
- 져도 0은 아닙니다 — 0이면 질 것 같을 때 나가 버리는 편이 이득이 되기 때문입니다.

**온라인 대전(1:1 · 2대2 · 릴레이)** 은 시즌 기록을 남기지 않고, 득점·완봉 보너스도 없습니다.
점수에 값을 매기면 그게 곧 승부조작의 대가가 되기 때문입니다. 하루 총량도 골드 1,200 ·
경험치 2,500으로 막습니다 (`onlineCap.ts`). 남은 한도는 선수단 화면 상단에 표시되고 매일
자정(로컬 시간)에 다시 채워집니다. 원장은 브라우저별 로컬 저장이라 서버 검증은 아니며,
캐주얼한 반복 파밍을 막는 선까지가 목적입니다.

### 아이템

아이템이 나오는 유일한 경로는 **리그를 끝까지 마쳤을 때의 1~3위 차등 보상**입니다.

| 아이템 | 효과 |
|---|---|
| 경험치보충제 (소/중/대/특대) | 선수 한 명에게 경험치 200 / 600 / 1,800 / 5,000 |
| 능력치초기화권 | 쓴 훈련 포인트를 전액 환급하고 능력치를 처음 상태로 되돌린다 |
| 부상치료제 | 부상을 즉시 없앤다 |
| 스테미나회복제 | 누적 피로를 완전히 없앤다 (투수 전용) |

골드는 1위 12,000 · 2위 6,000 · 3위 3,000이며, 아이템 구성도 순위마다 다릅니다.

### 경기 중 교체

투수 교체 외에 **대타 · 대주자 · 대수비**를 쓸 수 있습니다. 타순에 들어 있지 않은 벤치 타자
중에서 고르며, 한 번 교체돼 나간 선수는 그 경기에 다시 나오지 못합니다.
지금은 CPU 대전과 리그에서만 쓸 수 있습니다 (온라인은 프로토콜 확장이 필요합니다).

### 규칙

실제 야구 규칙을 따릅니다 — 3스트라이크/4볼, 2스트라이크 이후 파울은 스트라이크 아님
(단 번트 파울은 삼진), 포스아웃·병살·야수선택, 태그업 희생플라이, 인필드 플라이,
폭투, 몸에 맞는 공, 끝내기, 연장(최대 3이닝).

**피치 클락 20초** — 투구 전 대기가 20초를 넘기면 위반입니다. 투수가 넘기면 자동 볼,
타자가 넘기면(CPU전에서 타석에 들어서지 않을 때) 자동 스트라이크가 선언됩니다.
남은 시간은 상단 카운트 옆에 표시되고, 타자·투수 교체나 다음 투구마다 다시 감깁니다.
온라인에서는 호스트만 위반을 판정합니다. 시간은 `PITCH_CLOCK_SEC`
([constants.ts](src/lib/game/constants.ts))에서 바꿉니다.

**설정에서 조절 가능**: 효과음·관중석·배경음 각각 켜기/끄기 및 볼륨, 정규 이닝(7/9),
콜드게임(발동 이닝·점수차), 지명타자, 투구 체감 속도, 카메라 흔들림.

**카메라 흔들림** — 배트에 맞는 순간 시선이 짧게(0.42초) 흔들리고 타구속도에 비례해 커집니다.
위치가 아니라 각도를 흔들기 때문에 타자 시점이든 스카이뷰든 같은 세기로 전달됩니다.
세기는 타구속도만 보고 정하므로 안타인지 아웃인지를 미리 알려 주지 않습니다.

### 사운드

투구, 포구, 타격, 번트, 헛스윙, 안타/홈런 관중 환호와 심판 콜은 Web Audio API로
재생합니다. 경기 외 화면의 배경음은 아래 위치에 직접 넣은 MP3 파일을 반복 재생합니다.

```text
public/audio/bgm/menu.mp3
```

파일이 없어도 게임은 정상 동작하며 배경음만 재생되지 않습니다.

## 밸런스 검증

엔진은 결정론적 시드 기반이라 헤드리스로 대량 시뮬레이션할 수 있습니다.
`balance.test.ts`가 180경기(=360 팀·경기)를 돌려 아래 지표가 범위를 벗어나면 실패합니다.

| 지표 (팀·경기당) | 이 게임 | MLB |
|---|---|---|
| 득점 | 4.34 | 4.5 |
| 안타 | 8.51 | 8.7 |
| 홈런 | 1.16 | 1.15 |
| 2루타 | 1.64 | 1.65 |
| 3루타 | 0.14 | 0.14 |
| 볼넷 | 2.67 | 3.2 |
| 삼진 | 8.61 | 8.5 |
| 타율 | .246 | .248 |

타구 물리는 실제 항력·양력 계수를 사용합니다 (186km/h·28° → 147m).

자동 시뮬레이션도 지친 투수를 불펜으로 교체합니다. 이게 없으면 선발이 9이닝을 완투하며
140구를 던지고, 후반에 제구가 무너져 볼넷과 득점이 실제보다 크게 부풀려집니다.

### 온라인 대전 아키텍처

**호스트 권위(host-authoritative)** 모델입니다.

```
게스트                     호스트
  │   HELLO(팀) ─────────────▶│
  │◀───────────── HELLO(팀)   │
  │◀───────────── START(초기 상태)
  │                           │
  │  (수비 시) PITCH ────────▶│
  │◀──────── PITCH_GO(구종·코스)   ← 양쪽이 같은 시드로 같은 궤적을 그린다
  │  (공격 시) SWING ───────▶│
  │◀──────── RESULT(판정 + 상태 스냅샷)
```

엔진이 시드 기반 결정론이므로 게스트도 같은 상태에서 같은 결과를 재현·검증할 수 있고,
호스트만 판정하므로 상태가 갈라지지 않습니다.

### 2대2 올스타전

네 명이 두 팀으로 나뉘어 붙습니다. 같은 편 두 사람이 **각자 자기 팀에서** 선수를 반씩 골라 와
하나의 올스타 팀을 만들고, **타석에 자기 선수가 섰을 때만** 조작합니다.

| 항목 | 규칙 |
|---|---|
| 선수 선발 | slot 0이 야수 5명, slot 1이 야수 4명 + 각자 투수 2명 |
| 타순 | 두 사람을 번갈아 배치 (slot 0 → 1·3·5·7·9번, slot 1 → 2·4·6·8번) |
| 공격 조작 | 타석에 선 선수의 주인만. 팀원 타석에는 관전 |
| 수비 조작 | 마운드에 선 투수의 주인만. 자기 불펜을 올리면 조작권이 넘어온다 |
| 선발 투수 | 두 사람이 낸 투수 4명을 섞어 **무작위** 추첨 (시드 기반) |
| 지명타자 | 항상 사용 (라인업이 야수 9명이므로) |

연결은 호스트를 허브로 하는 **별 구조**입니다. 게스트끼리는 직접 연결하지 않고
모든 메시지가 호스트를 거쳐 중계되므로, 1:1과 같은 호스트 권위 모델이 그대로 유지됩니다.

```
        게스트A
          │
게스트C─호스트─게스트B
```

1:1은 방 문서에 offer/answer를 한 쌍 두지만, 2대2는 게스트가 3명이라
`rooms/{roomId}/peers/{uid}` 문서를 게스트마다 만들고 **게스트가 offer를, 호스트가 answer를**
씁니다. 덕분에 호스트가 몇 명이 들어올지 미리 알 필요가 없습니다.

경기 중 누군가 연결이 끊기면 호스트가 그 사람의 선수를 인계받아(`PARTY_OWNERS`) 경기가 멈추지
않게 합니다.

### 2~7인 릴레이 타격 대결

개인전이며, 한 라운드에는 입장 순서상 한 명만 투수를 맡고 나머지 참가자가 각 1타석을
진행합니다. 모든 참가자의 투구 기회를 맞추기 위해 10라운드 이내에서 현재 인원수의 배수만
선택할 수 있습니다. 일반 안타·볼넷·사구는 1점, 홈런은 3점이며 수비와 주루는 사용하지 않습니다.

호스트가 모든 투구·스윙 판정과 순환 상태를 확정합니다. 입력에는 `turnId`와 `pitchSeq`를 넣어
늦거나 중복된 명령을 거부하며, 경기 중 기권자는 이후 차례와 순위에서 제외합니다. 현재 투수가
기권하면 그 투수 라운드에서 아직 확정되지 않은 점수만 롤백합니다.
